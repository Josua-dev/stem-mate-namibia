# ACCESSIBILITY_EVIDENCE.md — STEMMate Namibia v1.0.0

Evidence table for the WCAG 2.2 AA accessibility work. Results record only
what was actually verified in this build, and each row names the verification
method used:

- **Automated** — `npx impeccable detect src` exits 0 (clean), or a Vitest unit test run.
- **Computed** — WCAG contrast ratio calculated from the shipped hex values.
- **Code inspection** — the shipped source was read line-by-line and the
  attribute/behaviour confirmed in the cited file.

No browser-assisted (screen reader / manual zoom) run was performed for this
evidence; checklist cases 15–17 in TEST_CHECKLIST.md are provided for manual
execution and their Pass/Fail boxes are left for the assessor.

| # | Check | WCAG 2.2 Criterion | Issue Found | Fix Made | Result |
|---|-------|--------------------|-------------|----------|--------|
| 1 | Skip link | 2.4.1 Bypass Blocks | Skip link used `sr-only-focusable`, a class Tailwind does not ship — the link existed in the DOM but never became visible or usable on focus. | Rewritten in `src/components/SkipLink.tsx` with `sr-only focus:not-sr-only focus:absolute focus:top-2 focus:left-2 focus:z-50 focus:bg-blue-700 focus:text-white`; jumps to `#main-content`. | Verified — code inspection + CSS emitted in build |
| 2 | Visible focus | 2.4.7 Focus Visible | No issue in final code (verified after pass). | Every interactive element carries `focus:ring-2` with a visible offset; verified across all six pages. | Verified — code inspection; detector clean (exit 0) |
| 3 | Keyboard operation | 2.1.1 Keyboard | Plan delete and data reset used `window.confirm` — native dialogs that cannot be operated reliably and are announced inconsistently. | Created `src/components/ConfirmDialog.tsx` (`role="alertdialog"`, `aria-modal`, labelled title/description); wired into plan deletion and Settings reset. | Verified — code inspection; build 0 errors |
| 4 | No keyboard trap | 2.1.2 No Keyboard Trap | Activity details and plan-form dialogs had no focus containment — Tab escaped the dialog into background content. | Added Tab traps to both dialogs: Tab/Shift+Tab cycle within the dialog, Escape always closes, focus returns to the previously focused element (`src/pages/Activities.tsx`, `src/pages/Plans.tsx`). | Verified — code inspection |
| 5 | Dialog semantics | 4.1.2 Name, Role, Value | The two in-page modals used `role="dialog"` without a focusable close affordance order or labelled heading in some states. | Both dialogs carry `aria-modal="true"`, `aria-labelledby` pointing at a `tabindex="-1"` heading that receives focus on open. | Verified — code inspection |
| 6 | Status messages announced | 4.1.3 Status Messages | Sync results and connection changes changed pixels only — no live region. | Connection chip in the top bar uses `aria-live="polite"` (`AppShell.tsx`); sync result summary uses `role="status"`; save/remove toast uses `role="status" aria-live="polite"`; form errors use `role="alert"`. | Verified — code inspection |
| 7 | Non-colour status cues | 1.4.1 Use of Colour | No issue in final code. | All states pair emoji glyphs with text words: 🟢 Online / 🔴 Offline / ✅ Synced / ⚠ Pending / ❌ Failed; status text also spells the state. | Verified — code inspection |
| 8 | Text contrast | 1.4.3 Contrast (Minimum) | Two issues found: (a) `text-gray-400` (#9ca3af) on white computed at **2.54:1** — used for the Sync Queue empty-state text, both modal close glyphs and list bullets; (b) no computed check had been done on the accent. | (a) Bumped to `text-gray-500` (4.83:1) / `text-gray-600` (7.56:1); bullets marked `aria-hidden`. (b) Accent re-tuned to Yves Klein Blue #002FA7. | Verified — computed: #002FA7 on white **10.7:1**; gray-600 7.56:1; gray-500 4.83:1; white on #002FA7 10.7:1; dark-mode pairs ≥ 4.5:1 |
| 9 | Focus on route change | 2.4.3 Focus Order | Route changes left focus wherever it was — keyboard and screen-reader users had no signal that the page changed. | `src/components/RouteFocusManager.tsx` sets `tabindex="-1"` on the new page's `h1` and focuses it on every `location.pathname` change. | Verified — code inspection |
| 10 | Labels on inputs | 3.3.2 Labels or Instructions | One Settings import input had a broken `htmlFor="undefined"` label. | Fixed with a real `id="import-file"` + matching `htmlFor`; every input/select/textarea across all pages verified to have a paired label. | Verified — code inspection |
| 11 | Target size | 2.5.8 Target Size (Minimum) | No issue in final code. | All action buttons carry `min-h-[44px]` (exceeds the 24px AA minimum; meets the 44px best practice the product spec asks for). | Verified — code inspection |
| 12 | Reflow at 320px | 1.4.10 Reflow | The sidebar was a fixed 256px column on every viewport — at 320px it left a 64px content strip. | Sidebar is collapsed by default below 768px (`window.matchMedia` in `AppShell.tsx`), closes on navigation on small screens, and can be toggled with an `aria-expanded` button; content grids stack to one column. | Verified — code inspection; detector clean |
| 13 | Zoom 200% | 1.4.4 Resize Text | No fixed font sizes found (all sizing is rem-based). | Font-size setting scales the root (`[data-font-size="large"]` 18px / `"xl"` 20px), so every rem-based utility grows with browser zoom and the setting. | Verified — code inspection + CSS emitted |
| 14 | Reduced motion | 2.3.3 Animation from Interactions | The page-loader spinner spun unconditionally. | `@media (prefers-reduced-motion: reduce)` disables `animate-spin` only — an intentional alternative that keeps state-change feedback (hover colour changes and status text remain); no global motion kill. | Verified — CSS inspection (`src/styles/index.css`) |
| 15 | Error recovery guidance | (Resilience — product requirement) | The error boundary was a stub (`useState`, no `componentDidCatch`) — it never caught anything; failures showed a blank screen. | Rewritten as a real class component (`getDerivedStateFromError` + `componentDidCatch`) with calm recovery guidance: "Your saved activities, plans and requests are safe on this device…" and a working Try again button. | Verified — code inspection; build 0 errors |
| 16 | Dark mode contrast | 1.4.3 Contrast (Minimum) | Dark-mode toggle previously did nothing visually — pages used light-mode utility classes only. | `.dark` override block in `src/styles/index.css` remaps surfaces, text, borders and tinted status chips; dark pairs verified to keep ≥ 4.5:1 for body text. | Verified — computed + code inspection |
| 17 | Privacy validation before save | (Product requirement — data minimisation) | Two defects found by the unit tests: (a) the S-prefixed ID pattern lacked the case-insensitive flag so it could never match (values are lowercased before testing); (b) the blocked-word list included verb-colliding words (`record`, `mark`, `score`, `grade`, `class`) that over-blocked legitimate instructional text ("Students record their observations", "a class of learners"). | (a) Added `i` flag to the S-pattern. (b) Tightened the data-word list to unambiguous pupil-data terms. | Verified — Vitest: 39/39 unit tests pass (`npx vitest run`), including both regression cases |
